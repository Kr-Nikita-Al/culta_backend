# Статусы аккаунта и email-коды

Глобальные статусы: pending (Создан), confirmed (Подтверждён), blocked,
deleted. HTTP и WebSocket проверяют статус при авторизации. Существующий
токен не даёт доступ заблокированному пользователю. Открытый WebSocket
повторно проверяет права по существующему механизму не реже чем раз в 30 секунд.

Миграция f25c13e62026 подтверждает активные аккаунты с привязкой YANDEX,
неактивные помечает deleted, остальные — pending. Балансы, роли и история
не изменяются. Перед миграцией нужна резервная копия. Автоматический downgrade
запрещён: удаление статуса могло бы восстановить доступ заблокированным аккаунтам.

POST /login/email/request-code: email, password. POST /login/email/confirm:
те же поля плюс шестизначный code. Требуется правильный пароль. Код действует
10 минут, допускает 5 попыток и одно успешное использование. Повторная отправка
возможна через 60 секунд и отменяет предыдущий код. Конкурентные запросы
сериализуются блокировкой строки пользователя. Хранится HMAC кода, не сам код.

Без настройки доставка возвращает 503. Локальная доставка включается только
при ENV=local (или development/dev/test) И EMAIL_DELIVERY_MODE=local.
EMAIL_LOCAL_OUTBOX задаёт каталог тестовых писем (по умолчанию
.local-email-outbox в корне backend, исключён из Git). Права каталога 0700,
файлов 0600. Письма доступны только на диске разработчика: публичного API,
вывода кодов в логи и отправки наружу нет. Удаляйте тестовые письма после
использования. В production локальная доставка запрещена даже при указанном mode.

SMTP включён по умолчанию (EMAIL_DELIVERY_MODE=smtp). Задайте SMTP_USERNAME,
SMTP_PASSWORD (пароль приложения), SMTP_FROM, SMTP_FROM_NAME. Для Mail.ru
по умолчанию SMTP_HOST=smtp.mail.ru, SMTP_PORT=465, SMTP_SECURITY=ssl.
Другой сервер можно настроить через эти переменные; поддерживается также
starttls, без отключения проверки сертификата. Локальный и серверный backend
читают собственный .env: секреты не передаются в UI. Изменение .env требует
перезапуска процесса. В SMTP-режиме коды не пишутся в локальный почтовый ящик.
При ошибке доставки API возвращает 503 без ответа SMTP-сервера и откатывает код.
При сетевой ошибке после приёма письма провайдером доставка может быть
неопределённой: автоматического повтора нет, пользователь запрашивает новый код.

ACCESS_SUPER_ADMINS разрешает получение роли, но не доказывает владение email.
Регистрация email сохраняет пользователя, приветственную бонусную запись,
базовую роль и QR в одной транзакции. Сбой любого шага откатывает регистрацию.
Пустая папка пользователя в S3 не создаётся: текущие изображения хранятся
в пространстве компании. Доступность S3 не влияет на регистрацию.
Новые pending-аккаунты из списка проходят подтверждение email или проверенный
OAuth на общих основаниях. Пароль и старый токен не подтверждают pending-аккаунт.
Уже подтверждённые аккаунты сохраняют доступ. blocked/deleted не восстанавливаются.

На публичном
развёртывании также нужен rate limit на уровне ingress для регистрации,
логина и проверки пароля; лимиты кода не заменяют защиту от перебора паролей.

Вход через существующий Яндекс подтверждает pending, но не восстанавливает
blocked/deleted. Неподключённые провайдеры скрыты в UI. Смена email через
обычный профиль запрещена до отдельного процесса проверки нового адреса.

Яндекс OAuth запускается через GET /login/auth/yandex: сервер устанавливает
подписанную HttpOnly-cookie на 10 минут и передаёт случайный state провайдеру.
UI возвращает code и state в callback с withCredentials. Без совпадающей
cookie, при неверной подписи или истёкшем сроке обмен кода не выполняется.
После успешного входа cookie удаляется. Старые незавершённые попытки входа
нужно начать заново кнопкой Яндекса. Отсутствующий default_phone допустим.

GET/PATCH /user/account_status доступны только глобальному суперадмину.
PATCH принимает status и expected_status (409 при конфликте), сохраняет
updater_id/time_updated и сбрасывает код. Статус самого суперадмина через этот
API не меняется. deleted — мягкое удаление, финансовая история сохраняется.
